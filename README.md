# RHODIZ Harness Desktop

Windows desktop client for the RHODIZ Harness runtime.

The desktop is **not** a second coding/runtime authority. The certified Harness Core remains authoritative for Project/Session isolation, signed workspace leases, capability enforcement, Landlock confinement and resource governance.

## Architecture

- **Tauri 2** host shell with React + TypeScript renderer.
- **Narrow Rust broker** owns Windows/WSL lifecycle operations.
- Renderer receives only explicit, typed IPC commands.
- Managed Linux runtime lives in the dedicated `RHODIZ-Harness` WSL2 distro.
- Docker/Compose, RHODIZ MCP Route, RHODIZ Memory MCP and provider sidecars remain private to the managed runtime.
- Normal coding work uses Core contract v1 and explicit `coding` Sessions.

## Current milestone

`0.1.0` establishes the secure Desktop foundation:

- local-only renderer with strict CSP;
- production DevTools disabled;
- one IPC command: `runtime_status`;
- no generic shell/process Tauri plugin;
- fixed `wsl.exe --status` probe;
- fail-closed runtime state model;
- provenance anchors for OpenHands, Onyx and LibreChat;
- local Test-Automator coverage and Rust broker tests.

## Verification

```text
npm run lint
npm run test:coverage
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo test --manifest-path src-tauri/Cargo.toml -p rhodiz-harness-broker-core
cargo clippy --manifest-path src-tauri/Cargo.toml -p rhodiz-harness-broker-core --all-targets -- -D warnings
```

`verify:portable` composes the portable gates. Native Tauri/Windows packaging and Windows E2E must be certified on a Windows environment; a Linux cross-check is not treated as equivalent evidence.

## Security invariants

- no renderer-provided executable, argv, PowerShell, WSL, Docker or generic process capability;
- app commands are ACL-generated by `AppManifest` and explicitly granted per Tauri capability;
- capability `main-runtime-status` is Windows-only, local-only and grants only `allow-runtime-status`;
- no remote code/navigation or backend bearer persistence in the renderer;
- runtime releases will be accepted only through signed manifests, exact digests and anti-rollback sequencing.
